# 行囊实施计划 v0.1

## 2026-10-12 投递版完善（用户已授权整轮执行与验证）

依次完成手动添加、独立示例与新计划入口、诚实的链接留存说明、可配置 AI 提取与规则兜底、全国城市查询、共享线上/本地 API、异常与本地保存提示、回归测试与 CI、README/截图/演示资料、Git 初始化及上线。每项在推进前执行相关验证；账号登录、外部域名配置和模型密钥缺失记为外部待办，不能把未部署或未配置的能力记为已上线。

验收：首次体验可走通导入、候选确认、位置确认和按天整理；示例不会覆盖用户计划；未配置模型时明确使用规则；服务端密钥不入 Git 或前端；测试和构建通过；公开链接仅在实际部署成功后交付。

本轮状态：代码与本地 Git 提交、16 项自动测试、类型检查、构建、桌面流程、截图和文档已完成。GitHub/Vercel 发布及线上地图域名仍待登录与配置；手机视口实测待完成。模型未配置属于用户主动选择，后续可接入，不能当成已验证的 AI 能力。

## 当前里程碑

先完成不依赖地图 Key 或小红书内容授权的本地闭环：用户选择城市，粘贴攻略文字，确认 POI，将其整理进标签池与旅行脑图，并在刷新后恢复计划。

用户验收当前步骤后，才能开始下一步骤。

## 计划步骤

### 1. 建立 React + TypeScript 应用骨架

将现有单页原型迁入 React + TypeScript + Vite 项目，保留可启动的首页与现有视觉基调，不接入地图或外部接口。

**验收：** 本地开发服务可启动；首页可打开；浏览器控制台没有阻断性错误。

### 2. 定义旅行计划状态与本地保存

实现一份旅行计划的数据模型、初始状态与版本化本地保存。此步只处理模拟 POI，不包含导入界面。

**验收：** 修改旅行天数或模拟 POI 状态后刷新页面，数据能恢复；无效或缺失的本地数据不会使页面崩溃。

### 3. 创建旅行计划

提供中国大陆城市名称与 2–5 天选择；创建或修改计划时更新根节点标题。缩短天数时，把超出日期的 POI 转为未安排，保留其优先级。

**验收：** 用户能创建一个城市计划；从 4 天改为 2 天后，原 Day 3 和 Day 4 的地点仍存在于未安排地点池，原优先级不变。

### 4. 文字攻略导入与候选 POI 识别

提供文字粘贴入口，针对用户提交文字产生可编辑的地点候选；候选识别优先利用清单结构、过滤描述性路线词，并将交通站点单独标记为交通参考，不把结果当作已确认地点。

**验收：** 粘贴包含多个地点、路线描述和地铁站的文字后，用户能看到旅行 POI 与交通参考；路线描述不作为候选，用户能修改名称或取消候选。

### 5. 候选确认、分类、来源与去重

让用户确认候选地点及类别；为文字导入记录来源；按标准名称合并重复候选与已有 POI，来源累加而不是重复建点。

**验收：** 两次导入同一地点后，标签池只出现一个 POI；其详情可显示两条来源记录。

### 6. 标签池与旅行脑图整理

实现分类筛选、必去、待定、Day 1–Day N 节点，并将“优先级”与“安排日期”拆为独立维度；支持点击及拖拽分别修改两者，所有变更立即保存。

**验收：** 用户能将一个“必去”地点同时安排到任意 Day；脑图只在该 Day 显示它，并带必去标记；改变天数后地点日期可清空但优先级不丢失，刷新后安排不变。

### 7. 完成首个本地闭环验收

用一段真实旅行攻略文字走完“城市 → 文字导入 → 候选确认 → 标签池 → 脑图安排 → 刷新恢复”的完整流程，修复本里程碑暴露的问题。

**验收：** 用户亲自完成一次端到端操作并确认该闭环可用。

### 8. 接入地图配置与受控降级

加入高德地图 JS API 的加载、Key 配置说明和未配置时的占位界面。此步不查询 POI。

**验收：** 有效 Key 时显示当前城市底图；没有 Key 时仍可使用文字整理闭环，并看到明确说明。

### 9. 接入按需 POI 候选查询与位置确认

通过服务端接口按“地点名称 + 城市 adcode”查询地图候选，让用户确认名称、地址与位置；只保存确认后的地图 POI ID、坐标和地址。

**验收：** 同名地点返回多个候选时可人工选择；未确认地点不会被显示为准确地图标记。

### 10. 实现地图与脑图双向联动

在地图标记中使用与脑图一致的状态颜色；实现脑图定位高亮地图标记，以及地图标记打开相同 POI 详情。

**验收：** 两个方向均可打开同一 POI；修改状态后对应标记颜色同步变化。

### 11. 加入攻略来源库、批量链接任务与文字兜底

实现以笔记为单位的攻略来源库：每张来源卡可显示标题、可点击的原始小红书链接、处理状态和关联 POI。实现多条链接的逐条任务状态、失败原因与原位文字粘贴入口；链接读取接口在没有合规服务前仅返回明确不可用状态，但链接和用户补充的标题必须仍被保存并可回看。

**验收：** 多条输入中一条失败不会阻断其他任务；失败项可以直接粘贴文字并继续进入相同确认流程；用户能从任一 POI 查看来源攻略，也能从来源卡查看它关联的所有 POI 并打开原帖。

### 12. 评估并接入合规的公开笔记内容读取能力

**当前状态：延期。** 在取得可验证的内容访问授权或服务商书面数据使用许可前，不执行接入；现有“链接留存 + 文字兜底”闭环继续作为产品默认能力。

只有在取得平台授权或验证可持续、合规的内容服务后，才替换链接读取适配器；保留文字兜底与来源链接。

**验收：** 已确认授权范围、失败处理与数据使用规则；链接成功与失败均不破坏既有导入闭环。

### 13. 将交通参考升级为可整理的交通节点

新增“交通”主分类及地铁站、火车/高铁站、机场、公交站、码头、停车点等交通种类。交通候选默认不选但可加入地点池；地点池把游玩与消费地点和默认折叠的交通节点分组展示。交通节点复用现有来源、优先级、日期安排和地图确认能力。

**验收：** 导入含地铁站的文字后，候选确认页能勾选该交通节点并显示交通种类；加入后它在地点池的“交通节点”区显示，刷新后分类仍保留，且可安排到 Day N 与确认地图位置。

地图维持第一版的城市初始视野与简洁画面，不展示比例尺、缩放控件、全览按钮或额外提示层。地图标记首次轻点只聚焦，第二次轻点同一标记才显示详情；切换标记只切换聚焦，关闭详情时清除聚焦。普通地点与交通节点使用紧凑、不同形状的标记，并为位置很近的标记做轻微错位以降低遮挡。

地图打开的地点详情中，在默认收起的攻略来源之前展示可自动保存的个人备注，用于记录玩法、打卡或提醒；备注刷新后仍可恢复。

地点池标题的管理菜单提供“清空地点池”。该操作必须二次确认，仅清空 POI 和其安排、地图确认信息及备注，保留攻略来源库。

### 14. 地图与旅行安排同屏工作台（已获用户授权）

在原项目实施，版本一备份保持不变。桌面左侧地点池、右侧地图，右侧底部是可收起的旅行安排面板。分组条显示全部、必去、待定及各 Day 的数量；选择分组突出地图对应地点，其他地点淡化但可点击。安排面板支持拖拽，点击地点聚焦地图。地点卡以不遮住整个工作台的形式提供优先级、日期、备注和折叠来源。地图保留首次点击 18 级聚焦、再次点击打开卡片；关闭卡片、修改数据或切换分组不重置视野。聚焦后显示“全览地点”，可收起卡片并按所有已确认位置恢复缩小全览。

验收：地图与安排同屏；折叠面板释放地图空间；修改日期立即同步分组与标记；备注及安排刷新保留；各分组可切换且无相机跳动；旧版本文件未修改。

### 15. 单日编辑页（已获用户授权）

在总览的每个 Day 分组提供“编辑”入口，并支持再次点击已选 Day 分组进入该日期的独立编辑页。页面只处理当前 Day：编号地图与时间线互相高亮、紧凑的上午/下午/晚上标签与地点备注、从未安排地点加入，以及通过拖拽把手调整当日顺序。单日页不提供日期选择或上移/下移排序按钮；跨天取舍仍在总览完成。时段、地点备注和排序均保存到本地；不实现自动路线、实时交通或自动排程。

**验收：** 用户可从总览进入任一 Day 页面；未安排地点加入后即时同步总览；地图仅显示当前 Day 的已确认地点并按顺序编号；地点可拖拽排序并立即同步编号地图；时段、地点备注与排序刷新后保留；返回总览不丢失全局地图视图或其他 Day 的安排。

### 16. 单日手动交通段（已获用户授权）

在单日编辑页的相邻地点卡之间展示紧凑交通段。用户可手动选择步行、地铁、公交、打车、自驾、骑行或其他，并按需填写预计分钟数。交通段仅表示用户的行程设想，不请求路径规划、实时交通或自动时长；只保留同一天仍相邻的起终点组合，改变顺序或日期后失效段自动移除。

**验收：** 当天有两处以上地点时，每组相邻地点之间可设置交通方式和预计时长；刷新后数据恢复；重新排序或改变地点日期后，不再相邻的交通段不会显示或保留；不影响既有地点卡、地图编号和未安排地点加入。

### 17. 交通节点与交通段关联（已获用户授权）

在每条手动交通段中提供“经交通节点”选择，候选来自地点池中未安排或属于当前 Day 的交通 POI。选中节点后复用其名称、类型、来源和确认地图位置；地铁站与公交站默认填入相应交通方式。被引用且位置已确认的交通节点显示在当前 Day 地图中，但不加入游玩地点时间线或编号排序。删除节点时仅清空相关交通段的节点引用，保留手动方式和分钟数。

**验收：** 用户可为交通段选择地点池中的交通节点；选择后交通段显示该节点，地图以未编号交通标记显示其已确认位置；刷新后关联仍存在；取消或删除节点不会删除该交通段已有的方式和分钟数。
