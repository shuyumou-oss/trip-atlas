# 行囊技术栈 v0.1

本文件从 `design-document.md` 推导，用于实现“批量导入攻略内容 → POI 确认、去重与来源保留 → 标签池、脑图与真实地图联动”的第一版闭环。

## 1. 技术选择

| 层级 | 选择 | 本版本职责 | 选择原因 |
|---|---|---|---|
| Web 应用 | React + TypeScript + Vite | 导入流程、标签池、脑图、详情卡和地图容器 | 组件与状态较多；TypeScript 能约束 POI、来源和导入状态，Vite 保持本地开发简单快速。 |
| 样式 | CSS（保留并逐步迁移现有 `style.css`） | 页面布局、状态色、响应式界面 | 第一版不引入额外设计系统，便于延续当前原型并控制复杂度。 |
| 页面状态 | React `useReducer` + Context | 当前计划、攻略来源库、POI（含交通节点）、导入任务、选中 POI、地图联动状态 | 状态范围只在一个单页应用内，暂不需要额外状态管理库。 |
| 拖拽 | dnd-kit | 将 POI 拖至必去、待定或 Day 节点 | 支持键盘操作与可控的拖拽状态，适合脑图整理交互。 |
| 本地持久化 | `localStorage` | 保存单份计划、POI、来源、地图确认结果和天数 | 符合无账号、单设备、刷新可恢复的第一版范围。 |
| 地图展示 | 高德地图 JavaScript API 2.0 | 底图、标记、地图平移、高亮与点击事件 | 提供中国大陆地点的真实地图呈现，匹配产品首版地域范围。 |
| POI 查询 | 高德地图 Web 服务 POI 搜索 | 用“地点名 + 城市 adcode”查询候选地点 | 按需查询，不建立全国全量 POI 副本；用户确认后才持久化结果。 |
| 轻量服务层 | Node.js ESM + Web Request/Response | 代理 POI/城市搜索与可选模型提取；未来内容读取另行接入 | 共享本地及 Serverless 实现，密钥不进入前端。 |
| 部署 | Vercel 配置已准备，尚未发布 | 静态前端与四个 Serverless 接口 | 支持当前 Node 适配器；实际域名与地图配置待上线验收。 |
| 测试 | Node 内置测试 + TypeScript 转译钩子；浏览器人工验收 | 去重、状态、接口异常与提取校验 | 16 项回归测试无需另装测试框架；GitHub Actions 配置测试与构建。 |

## 2. 前端结构

前端拆为下列功能模块，避免把所有逻辑继续堆在一个 `app.js` 中：

```text
src/
  features/
    plan/          # 城市、天数与计划状态
    import/        # 批量链接 / 文字 / 手动输入与逐条状态
    poi/           # 候选确认、清洗、去重、来源和详情
    organizer/     # 标签池、脑图、点击与拖拽分配
    map/           # 高德地图初始化、标记与双向联动
  services/
    poi-search.ts  # 调用后端 POI 查询接口
    storage.ts     # localStorage 读写和版本迁移
  types/           # TravelPlan、POI、Source、ImportAttempt
```

这是目标目录而非立即创建清单；具体文件由实施计划逐步建立。

## 3. 数据与保存策略

- 浏览器仅保存用户已确认加入计划的 POI、来源记录、地图确认信息和安排状态；不缓存或复制全国全量 POI 数据。
- 来源以独立“笔记记录”保存，POI 仅保存关联的来源 ID；这样一篇攻略可关联多个 POI，来源库与 POI 详情也能双向展示同一份信息。
- `localStorage` 的根键采用版本化命名，例如 `trip-atlas:v1:plan`，便于未来升级结构。
- 写入前校验 `TravelPlan` 与 POI 的必要字段；读取失败或旧版本不兼容时，保留原始内容并提示用户重建，而不静默覆盖。
- 地图唯一 POI ID、经纬度和地址仅在用户确认候选后保存；交通节点与游玩地点共用同一确认与保存策略，并额外保存交通种类。
- 第一版没有账号与云端同步，因此浏览器数据清除后无法恢复；界面需明确这一限制。

## 4. 服务接口边界

### 4.1 POI 搜索接口

```text
POST /api/poi-search
输入：name、cityAdcode
输出：零到多个候选 { mapPoiId, name, address, adcode, longitude, latitude, category }
```

- 服务端使用地图服务密钥请求 POI 搜索；浏览器只调用本产品接口。
- 接口必须限制城市 / `adcode`，避免把同名地点匹配到别的城市。
- 不缓存地图服务返回的全量搜索结果；只将用户已确认的单个地点写入本地计划。
- 高德地图 API 的密钥、域名白名单和数据使用方式按其当前控制台与授权规则配置。

### 4.2 攻略内容读取接口

```text
POST /api/content-extract
输入：用户主动提交的链接
输出：{ status, title?, body?, originalUrl, failureReason? }
```

- 这是可替换的适配器接口，不预设抓取实现。
- 只有在获得平台授权或可验证的合规内容访问方案后，才接入真实链接读取能力。
- 在此之前，此接口对链接返回明确失败状态；前端必须立即显示“粘贴文字继续提取”，并让后续 POI 流程保持可用。
- 不读取用户小红书账号、收藏夹或私密内容，也不绕过登录、访问控制或平台限制。

### 4.3 POI 文本提取

第一版先采用可测试的规则化提取：地点名称候选由用户可编辑的文本片段、分隔符和已导入地点池共同辅助识别。它输出候选而非自动认定的结果，必须经过用户勾选及地图匹配确认。

后续如接入大模型，只能作为“从用户提交文字中找地点候选”的增强层；不能替代地图确认、去重规则或用户决定。

## 5. 安全与合规基线

- 地图 Web 服务密钥只保留在服务端环境变量；地图 JS API 使用受域名白名单约束的浏览器端密钥。
- 不在浏览器日志、页面源码或本地保存中写入服务端密钥。
- 只处理用户主动提交的攻略链接和文字，保存最少必要的来源信息。
- 链接内容读取是否可用取决于平台的授权与访问规则；不可用时坚持文字粘贴兜底，不能以技术手段绕过限制。
- 上线前复核高德地图的当前产品条款、API 配额、缓存及地图展示要求。

## 6. 运行与测试

本地开发使用 Node.js 24+、pnpm 10 管理依赖。开发环境需要：

```text
VITE_AMAP_JS_KEY                 # 浏览器地图密钥
VITE_AMAP_SECURITY_JS_CODE       # 高德安全密钥配置所需值
AMAP_WEB_SERVICE_KEY             # 仅服务端读取的 POI 搜索密钥
AI_API_KEY                       # 可选，仅服务端；未配置时使用规则
AI_BASE_URL                      # 可选，OpenAI 兼容 API 地址
AI_MODEL                         # 可选，所用模型名称
```

在未配置任何密钥时，应用应以“地图未配置”和“无法查询地点候选”的清晰占位状态运行，仍允许用户手动整理 POI。

每个实施步骤至少执行与其有关的测试；关键验收流程为：

1. 创建城市计划并刷新，计划仍存在。
2. 导入多条内容时，一条失败不阻断其余内容。
3. 文字兜底后可以得到、勾选并合并 POI，且原始链接仍可在来源库中打开。
4. 同一个地图 POI ID 只保留一个地点，来源可累加。
5. POI 的脑图状态变化会更新地图标记；地图点击能打开同一 POI。

## 7. 不在本栈中解决的事项

- 自动最优路线、交通时间、实时状态与预警。
- 自建或批量下载全国商业 POI 数据库。
- 账号、云同步、多人协作和线上内容收藏夹读取。
- 未获授权条件下的公开页面稳定解析。

## 8. 需要用户后续准备的外部配置

开始地图步骤前，用户需要在高德开放平台创建应用并准备 JS API 与 Web 服务的 Key，并为实际部署域名配置安全策略。链接真实读取能力则需先确认可用且合规的内容服务或平台授权；没有它时，产品依然按“粘贴文字”路径完成第一版闭环。
