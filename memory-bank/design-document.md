# 行囊设计文档 v0.1

## 当前选定视觉：浅色旅行册（2026-10-12）

用户最终选择最初的奶白旅行册图，而非后续深色或极简编辑式草稿。采用奶白 #FFFCF5、墨蓝 #18354F、主操作红 #C84F47；日期页签蓝/黄/绿，4–5 天延伸独立柔和色。主按钮小圆角、描边、短硬阴影及按下位移，次要操作轻量化。地点池用单行卡片：类别图标、名称、类别、真实来源数量、必去星标。星标只改变优先级，不改变日期；地图仍保留两次点击规则及真实高德地图和版权，不复制生成图的地理信息、来源认证和日期。单日页保留备注与交通按需展开。所有既有数据及版本一快照不变。

## 2026-10-12 工作台视觉首版

- 使用 frontend-design 指导的蓝白路线册方向：白色内容面、浅蓝灰画布、蓝色操作，地图作为主要视觉区域。
- 总览保留左地点池、右地图、下方安排；标题压缩为「地点池」「杭州旅行计划」。地点池总数包含交通，游玩分类的「全部」仅统计非交通地点；「已安排」仅统计已有日期的地点。
- 使用指南及计划备份入口收进顶部「更多」，行程设置与攻略导入常显。
- 单日页保留地图、今日行程与底部长条候选池。时段改为选择器；地点备注与交通段详情按需展开，交通摘要常显；增加单日切换选择器。
- 不修改 POI 数据结构，不改变地图两次点击规则，不自动生成交通估算，不接入新的抓取服务。

## 1. 设计目标

在不替用户决定“最优路线”的前提下，帮助自由行用户把分散的攻略地点收拢、去重、分类并可视化整理为自己的旅行计划。

第一版的完成闭环是：**一组用户提交的攻略内容 → 逐条提取、清洗和合并后的 POI → 经确认的标签池与旅行脑图中的个人安排**。

## 2. 范围与非目标

### 本版本范围

- 支持中国大陆任意城市；第一版一份旅行计划只规划一个城市。
- 单份本地旅行计划，旅行天数支持 2–5 天。
- 批量导入公开小红书笔记链接、攻略文字和手动输入地点。
- 链接解析成功后提取笔记标题、原始链接和 POI。
- 链接解析失败后，在同一导入流程切换至文字粘贴。
- 攻略来源库、POI 分类、别名去重、来源保留、标签池筛选、脑图整理及本地保存。
- 当前旅行城市的实际地图底图、已选 POI 的真实位置标记，以及脑图与地图双向联动。
- 全国 POI 按需查询与用户确认沉淀的数据策略。

### 非目标

- 自动生成路线、交通、预算和出行预警。
- 实时定位、实时拥堵、营业状态和天气等动态地图能力。
- 读取用户小红书账户、收藏夹或私密内容。
- 图片 OCR、多人协作、账号体系与云端同步。
- 在没有正式内容访问授权时，承诺稳定读取任意公开小红书页面。

## 3. 主要用户旅程

### 3.1 从攻略链接开始

1. 用户选择中国大陆旅行城市，系统保存该城市的名称与 `adcode`，再点击“导入攻略”。
2. 用户粘贴多条公开小红书笔记链接并提交。
3. 系统逐条尝试获取可读取的公开页面内容，并显示每条的处理状态。
4. 每条成功内容提取笔记标题、来源链接和候选 POI；失败内容保留文字粘贴入口。
5. 系统合并所有成功导入内容中的重复或别名 POI。
6. 用户在确认页勾选想加入的地点。
7. 系统将确认地点合并到标签池，并将每篇笔记保留在攻略来源库中；地点与来源笔记互相可追溯。
8. 用户分别设置地点优先级（必去 / 待定 / 普通）和安排日期（未安排 / 某一天），或拖动地点完成对应操作。
9. 用户可在地图上查看所有已选地点的实际位置；地图与脑图的地点选择状态同步。

### 3.2 链接失败后继续

1. 系统显示“无法读取此链接”及简短原因。
2. 同一界面展示攻略文字输入区，保留当前旅行计划。
3. 用户粘贴笔记正文或自己整理的文字。
4. 系统使用与链接解析相同的 POI 识别、确认和合并流程。

### 3.3 从地点池整理计划

1. 用户按类别筛选 POI。
2. 用户点击标签，或将标签拖入脑图节点。
3. 系统立即更新 POI 的优先级和所属日期。
4. 用户刷新页面后可恢复当前计划。

## 4. 功能行为

### 4.1 内容导入

| 输入 | 预期行为 |
|---|---|
| 多条公开小红书链接 | 后端内容读取服务逐条解析标题、正文和链接；每条独立记录处理状态与失败原因。 |
| 攻略文字 | 直接提交给 POI 提取流程。 |
| 手动添加 | 用户输入名称并选择类别；来源标记为“手动添加”。 |

链接解析服务只定义为一个可替换接口：它必须返回“成功 + 标题 + 正文 + 原链接”或明确失败原因。前端不依赖某一种特定抓取方式。

### 4.2 POI 提取、匹配和去重

1. 对每条成功内容，同一篇攻略内的重复名称先合并为一个候选 POI。
2. 所有导入内容之间再按标准化名称进行一次候选合并。
3. 以“地点名称 + 当前城市 `adcode`”查询地图 POI 服务。
4. 现有地点池已有相同地图 POI ID 时，不新建节点；为它追加一条来源记录。
5. 无法匹配、存在多个候选或用户跳过确认的地点作为“待确认地点”显示。
6. 用户确认后，才写入旅行计划与自有已确认 POI 库。

文字识别必须遵循以下准确性规则：

- 优先识别明确的清单结构（换行、序号、顿号、箭头、`#地点#`），而不是只按词尾截取整句话。
- 候选包含“经典、路线、全程、适合、交通、朋友、氛围、推荐”等描述性路线词时，不作为旅行 POI 候选。
- 识别到的地铁站、火车/高铁站、机场、公交站、码头与停车点作为“交通节点”候选显示。用户可勾选加入地点池；默认不选，避免把所有换乘站无意加入计划。
- 规则识别只产生候选，用户可编辑或移除；后续地图接入后，候选还需按“名称 + 当前城市 adcode”完成地图匹配确认。

地点池在界面上分为两组：上方为“游玩与消费地点”（景点、美食、咖啡与休闲、街区与购物、其他），下方为默认折叠的“交通节点”。交通节点的主分类为“交通”，并保留 `transportType`（地铁站、火车/高铁站、机场、公交站、码头、停车点、其他）以便筛选与显示；它们与其他 POI 一样可安排到某一天、完成地图确认和关联攻略来源。

地点池标题右侧提供“··· 管理”菜单。菜单中的“清空地点池”须经过二次确认，才删除当前计划的所有 POI、脑图安排、地图确认信息和个人备注；攻略来源库及原帖链接保留，第一版不提供撤销。

### 4.3 来源信息

攻略来源库以“笔记”为单位保存用户主动导入的攻略。每篇来源笔记可关联零到多处 POI，每个 POI 也可关联零到多篇来源笔记。来源信息包含：

```text
标题、原始链接、导入时间、导入方式（链接 / 文字 / 手动）
```

来源库卡片显示标题、导入方式、原始链接、处理状态和已关联 POI 数；用户点击卡片或 POI 详情中的来源标题，可打开原始链接。用户可在 POI 详情中编辑来源标题与链接，或删除该地点上的单条来源记录；标签池不直接展示长链接。

用户删除来源库中的一篇攻略时，系统先提示将受影响的地点数量；会删除该来源记录并移除其与 POI 的关联。只有没有其他攻略来源的 POI 才会随之从当前计划删除；仍有关联来源的 POI 必须保留。

地点详情将“我的备注”置于攻略来源之前，用户可写下该点的玩法、打卡内容或个人提醒；备注在离开输入框后自动保存并随本地旅行计划恢复。攻略来源默认收起，以紧凑字体显示；用户按需展开后才查看、编辑或删除来源记录。

即使链接尚无法被自动读取，也要保留为一篇可点击的来源笔记。用户可同时补充标题和攻略文字，以继续走文字 POI 提取流程；不能因为链接读取失败而丢失原帖的回看入口。

### 4.4 旅行脑图

新版工作台桌面左侧约 25% 为地点池，右侧为地图和底部可折叠的安排面板。收起后仍保留分组与数量；展开显示可拖拽的分组地点，地图相应缩小而不被面板遮盖。点击分组突出地图对应地点，其他地点淡化但仍可选；切换分组不自动调整地图视野。小屏幕将地点池与工作台纵向排列。

- 根节点显示当前旅行城市的旅行计划。
- 每个 POI 有两项互不冲突的整理信息：`priority`（必去 / 待定 / 普通）和 `scheduledDay`（未安排 / Day 1–Day N）。
- 脑图固定展示“必去”“待定”优先级节点及动态 Day 1–Day N 日期节点。
- 未安排日期的必去或待定地点显示在对应优先级节点；已安排的地点只显示在对应 Day 节点，若为必去则额外显示“必去”标记，避免同一地点重复出现。
- 修改旅行天数时，超出日期范围的地点变为未安排，原优先级保持不变。
- 拖到“必去 / 待定”只改变优先级；拖到 Day 节点只改变安排日期。点击与拖拽均即时保存。

### 4.4.1 单日编辑页

总览负责把地点分配到不同日期；单日编辑页只负责编排某一天的已有地点。用户第一次点击 Day 分组时仍在总览中突出该日期的地图标记；再次点击同一 Day 分组可进入单日编辑页。每个 Day 分组标题同时提供明确的“编辑”入口，作为触屏和新用户的可发现入口。

单日编辑页包含且只包含以下三个功能块：

1. **当日编号地图：** 仅显示当前 Day 已确认位置的 POI，按照当天时间线顺序显示 `1、2、3…`。点击地图标记与时间线地点卡会互相高亮。
2. **今日行程时间线：** 显示当天全部 POI，以紧凑地点卡展示名称、上午/下午/晚上标签及该地点的个人备注；不提供日期下拉或上移/下移按钮。用户可拖拽每张地点卡左侧的把手调整当天顺序，编号地图即时按新顺序更新。该时段是用户的整理标签，不代表系统已计算准确出行时间。
3. **当日地点管理：** 页面只展示当前计划中“未安排”的地点；点击可将其添加到当天末尾。第一版的单日页不提供移回未安排或跨天移动，用户可回到总览完成日期取舍；其他 Day 的地点不在候选区直接出现，避免误操作。

单日页通过“返回总览”回到原工作台。第一版不做自动排序、路线生成、实时交通、预算、营业状态或预警。

### 4.4.2 手动交通段与节点引用

交通节点（机场、地铁站等）是地点池中可复用的 POI；交通段则是同一天相邻两处地点之间的移动安排。单日编辑页在每两张相邻地点卡之间显示一条紧凑交通段，用户可手动选择步行、地铁、公交、打车、自驾、骑行或其他，并可选填预计分钟数。

- 交通段只记录用户自己的安排，不调用路径规划或实时交通接口，也不承诺时长准确。
- 只有当天至少有两处地点时才显示交通段；未选择方式或时长时显示“待补充”。
- 交通段以“起点 POI + 终点 POI”保存。地点被移出当天、删除、或拖拽后不再相邻时，对应交通段自动移除；仍相邻的段保留。
- 每条交通段可选填一个“经交通节点”，候选来自地点池中未安排或已安排在当天的交通 POI。选择后会复用其名称、地图位置、交通种类和攻略来源；地铁站、公交站分别默认补入“地铁”“公交”方式，但用户仍可改。
- 被交通段引用且已完成地图确认的交通节点，会在当天地图显示为未编号的交通胶囊，不占用游玩地点的时间线和排序。交通节点仍可被用户主动安排为当天行程的开头、中间或结尾。
- 删除被引用的交通节点时，会移除对应交通段的节点引用，但保留用户选择的方式与分钟数。

### 4.5 实际地图标记

- 地图以当前旅行城市为初始视图，并使用高德地图作为第一版地图服务。
- 每个完成地图确认的 POI 显示为一个真实地理位置标记。
- 标记颜色与旅行脑图状态一致：必去为红色、待定为黄色、已安排为绿色。
- 用户点击脑图中的 POI 时，地图平移至该 POI 并高亮标记。
- 用户点击地图标记时，打开与标签池相同的 POI 详情卡，支持查看来源、修改状态或删除。
- 对从攻略提取但尚未完成地图匹配的 POI，显示“待确认位置”状态，不在地图上标记为准确地点。
- 地图维持简洁画面，不展示比例尺和常驻缩放控件。用户聚焦地点后，在地图左上方临时显示“全览地点”；点击后收起地点卡、取消聚焦，并将所有已确认位置缩放进当前视野。只有一个已确认地点时，回到城市初始视野。
- 地图标记采用两次轻点交互：首次点未聚焦标记时，地图平移至该点并放大至 18 级聚焦视野，标记仅轻微高亮；再次点同一标记才打开轻量地点卡。点另一个标记只切换聚焦。关闭卡片保留视野；更新日期、备注和分组筛选不重新定位。地点卡顶部提供独立的优先级及日期选择，下面显示位置、备注、折叠来源。
- 普通地点使用紧凑圆形标记，交通节点使用更短的文字胶囊标记；名称最多显示四个字。地图会对距离很近的标记施加轻微错位，尽量减少遮挡，同时不改变其地图确认位置。

### 4.6 地图 POI 确认

1. 系统以“地点名称 + 当前旅行城市 `adcode`”查询地图 POI 服务，并严格限制结果位于该城市。
2. 若只返回一个高置信候选，系统预选该地点，用户仍可查看或修改。
3. 若返回多个候选，显示名称、地址与行政区，让用户选择准确地点。
4. 用户确认后，保存地图服务 POI ID、经纬度与标准地址。
5. 如果没有候选或用户跳过，POI 仍可进入标签池和脑图，但保持“待确认位置”。

## 5. 状态与数据模型

### TravelPlan

```text
id
cityName
cityAdcode
days = 2..5
pois[]
```

### POI

```text
id
name                 # 标准名称
category             # 景点 / 美食 / 咖啡与休闲 / 街区与购物 / 其他 / 交通
transportType        # 仅 category = 交通 时存在：地铁站 / 火车或高铁站 / 机场 / 公交站 / 码头 / 停车点 / 其他
aliases[]            # 预置别名
note                  # 用户的玩法、打卡与提醒备注，可为空
mapProvider           # 第一版为 amap，可为空
mapPoiId              # 地图服务的唯一 POI ID，可为空
longitude             # 已确认位置时存在
latitude              # 已确认位置时存在
address               # 标准地址，可为空
locationStatus        # confirmed / needs_confirmation / unavailable
priority             # normal / must / maybe
scheduledDay          # null / 1..5
dayPart               # null / morning / afternoon / evening；仅为手动整理标签
sources[]            # 零到多条来源记录
```

### Source

```text
id
title
url                  # 用户提交的原始链接，可为空
importedAt
method               # link / text / manual
parseStatus          # pending / succeeded / failed / text_only
poiIds[]             # 该笔记确认关联的 POI
```

### DayPlan

```text
day                  # 1..5
poiIds[]             # 当前 Day 的手动排序，且只包含 scheduledDay 相同的地点
note                 # 旧版兼容字段；当前单日页不展示或编辑
transportSegments[]  # 仅相邻 POI 之间的手动交通段，可为空
```

### TransportSegment

```text
fromPoiId
toPoiId
mode                 # walk / metro / bus / taxi / drive / bike / other，可为空
durationMinutes      # 用户填写的预计分钟数，可为空
viaPoiId             # 可复用的交通节点 POI，可为空
```

### ImportAttempt

```text
inputType            # link / text
inputValue
parseStatus          # pending / succeeded / failed
failureReason        # 仅失败时存在
candidates[]
```

## 6. 异常与边界情况

| 情况 | 产品处理 |
|---|---|
| 链接格式错误 | 不提交解析，提示用户检查链接。 |
| 页面不可访问、需要登录或内容读取失败 | 保留导入任务，并展示文字粘贴兜底入口。 |
| 多条链接中仅部分失败 | 成功链接继续进入合并流程；失败链接单独显示文字粘贴入口。 |
| 解析成功但没有识别到当前城市 POI | 提示用户检查内容，可手动添加地点或修改目的地城市。 |
| 识别到描述性路线词或交通站点 | 路线词不作为 POI 候选；交通站点作为默认未选中的交通节点候选，用户可选择加入地点池。 |
| 同一地点来自多篇笔记 | 合并为一个 POI，保留多个来源。 |
| 同名 POI 返回多个地图候选 | 用户确认准确地点后再保存地图 ID 与坐标。 |
| POI 尚未匹配地图位置 | 保留在标签池和脑图，不显示为准确地图标记。 |
| 用户删除 POI | 删除当前计划中的 POI 与其来源；操作在第一版不提供撤销。 |
| 用户清空地点池 | 删除全部 POI 与其相关安排、地图位置和备注；攻略来源库仍保留。 |
| 从 4 天改为 2 天 | Day 3、Day 4 中的 POI 变为未安排，必去 / 待定优先级不变。 |
| 减少旅行天数 | 被移出范围的 DayPlan 删除；其中地点转为未安排并清除其当日时段标签。 |
| 调整地点顺序或日期 | 不再属于同一天相邻地点的一条手动交通段自动移除；仍相邻的段保留。 |
| 删除被交通段引用的交通节点 | 清空该交通段的节点引用，但保留手动交通方式和分钟数。 |
| 浏览器本地数据被清除 | 仅可从用户此前导出的 JSON 备份恢复；没有备份时不能自动找回。页面明确仅本地保存。 |

## 7. 验收标准

1. 用户可创建中国大陆任意城市的 2–5 天旅行计划。
2. 用户可一次提交多条链接；每条都有可见的成功或失败状态，且单条失败不影响其他内容处理。
3. 成功内容经过跨攻略去重后生成带标题与链接来源的 POI 候选；失败内容无需离开页面即可粘贴文字继续。
4. 用户可取消候选 POI 后再加入地点池。
5. 同名或别名地点只生成一个 POI，并保留全部来源记录。
6. 用户可按类别筛选，并分别用点击或拖动设置地点的优先级与安排日期；必去地点可同时安排至 Day N 且仅在 Day N 节点显示必去标记。
7. 每个已导入 POI 的详情中能看到来源笔记标题及链接。
7.1 用户能在攻略来源库查看一篇笔记关联的所有 POI，并从任一 POI 详情回到对应来源笔记。
8. 已确认地图位置的 POI 在当前城市真实地图中以正确位置显示，且颜色与脑图状态一致。
9. 脑图与地图标记可双向打开同一个 POI 详情。
10. 改变旅行天数不会丢失超出日期范围的 POI，且保留其优先级。
11. 刷新页面后，旅行天数、POI 状态、来源信息及地图确认信息仍能恢复。
12. 用户可将交通节点候选加入地点池；地点池将游玩与消费地点和交通节点分组展示，交通节点能显示交通种类并完成与普通 POI 相同的安排和地图确认流程。
13. 用户可从地点池标题的管理菜单发起清空操作；二次确认后地点池、脑图与地图标记清空，但来源库保留。
14. 用户第一次选择 Day 分组时可在总览查看其地图地点；通过再次点击或“编辑”入口可进入对应单日编辑页。单日页可显示编号地图、紧凑的上午/下午/晚上标签及地点备注、相邻地点之间可引用交通节点的手动交通段，以及未安排地点加入；刷新后仍可恢复。

## 8. 已知产品风险

公开小红书笔记的稳定内容读取目前没有可确认的官方内容读取 API 支持。该功能需通过平台认可的访问方式实现；若无法保证，正式产品必须默认使用“粘贴文字”作为内容输入，链接仅作为用户可回看的来源信息，而不能宣称自动解析。

全国 POI 支持不意味着获取或维护全量商业 POI 数据。第一版仅在用户导入内容后按需查询地图服务，并保存用户已确认地点；地图服务数据的查询、缓存与展示必须遵守对应授权范围。

## 9. 求职投递版增补（2026-10-12）

- 首次访问提供创建个人计划、体验杭州示例和稍后再说入口；示例与个人计划互不覆盖。
- 用户可手动补充漏识别地点，后续仍需自行确认地图位置。
- 计划支持 JSON 导出和恢复；恢复覆盖当前计划前二次确认。数据只保存在当前浏览器，不声称云同步。
- 默认规则识别。可选模型接口已实现，但用户选择暂不提供 API Key；AI 入口明确显示未启用。配置后仍先生成带原文证据的候选，再由用户确认。
- 继续保持“链接留存 + 文字兜底”，不将个人登录浏览器抓取能力包装为可公开部署的正文服务。
- 发布验收与实际上线分开记录：接口及文档准备完成不等于 GitHub/Vercel 已发布，模拟测试也不等于真实模型效果验证。
