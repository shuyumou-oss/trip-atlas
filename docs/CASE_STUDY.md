# 行囊：从收藏攻略到个人旅行计划

## 观察

喜欢自由行的人会收藏大量攻略，但不同笔记围绕不同路线组织内容。用户在收藏夹、笔记和地图之间反复切换，仍难看清“我想去哪些地方、哪些邻近、哪天放在一起”。

这是项目起点。当前洞察来自个人旅行整理体验和产品讨论，不包装为已完成的大规模用户调研。

## 产品假设

以地点为整理单位、保留出处，并把地图与按天安排放在同一工作台，能够降低信息整理负担，让用户更容易做自己的决定。

## MVP 取舍

优先完成内容输入、候选确认、来源合并、地图确认和手动安排。将自动最优路线、实时预警、账号与云同步延期。链接正文读取受平台访问限制影响，保留可回看的来源卡片，并在界面明确当前需要文字输入。

AI 的角色是提取非结构化文字中的地点和证据，用户决定是否加入。当前提供可配置服务端接口与规则兜底；未配置模型 Key，不宣称实际使用了模型。

## 关键设计

- 优先级与日期分离：必去地点仍能安排进 Day 1，不需要在两种状态之间二选一。
- 地图与安排同屏：整理日期时能参考地点空间关系。
- 两次轻点标记：第一次看周边，第二次编辑详情，降低频繁弹窗打断。
- 来源多对多：同一地点可来自多个攻略；删除一篇来源仅删除无其他来源的关联地点。
- 交通节点复用：交通站点是 POI，交通段引用它而不是重新建立一套重复地点。
- 示例与个人计划分开：新用户能快速体验，又不会覆盖已有安排。

## 实现与验证

使用 AI 辅助开发完成 React、TypeScript、Vite 网页及共享服务端接口；持续通过产品体验反馈调整单日页面密度、地图联动、来源展示和交通安排。回归测试覆盖数据一致性与接口失败路径。

目前没有公开用户规模、留存或“提升 X%”数据。上线后建议邀请 3–5 位有真实旅行计划的用户完成任务，记录任务完成时间、错误次数和是否能够不依赖讲解完成一次安排。此计划尚未执行。
